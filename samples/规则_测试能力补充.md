## 0. 统一整合说明

- 本版本整合 Codex 测试专栏与 WorkBuddy“单模块测试点设计”空间中的测试规则；只吸收测试职责、测试设计和质量证据，不同步 WorkBuddy 的 Skill 文件、安装路径、宿主命令或非测试规则。资产包是正式主源；跨智能体运行层只保存按分类登记批准的必要副本。
- 全局入口为 `../01_全局规则/全局个人规则.md`；权威正文、能力补充和路由清单位于 `.`。任意会话、任意项目出现测试目标时适用，无须进入指定目录。
- `../02_项目规则/测试项目规则空间/test-project-rules.md` 为可选整理视图和局部补充，缺少它不影响中央测试规则的使用。项目需求与模板仍适用，项目旧副本不覆盖全局通用规则，不得关闭上层的证据、授权、中文路由、D 盘输出和不虚构结果约束。
- 边界值取值先按业务有效性和测试目标归类；“上点/离点”只表示相对边界的位置，不再固定映射为正向/逆向。

## 2. 复用能力的补足

- 计划必须含目标、依据、范围/不测范围、策略、环境/数据、资源排期、风险、准入准出、待确认项、交付与评审。排期列角色、负责人、工时、依赖、缓冲、完成条件；风险列概率、影响、信号、应对、回滚、责任人与阻塞性。缺排期/人员标假设，不强行凑 5 个问题。
- ERP 用例关注单据生命周期、审批/反审、库存冻结/释放、税汇折扣、账实一致、跨单据链路；迁移关注源目标映射、数量/金额/关联完整性、增量/双写、演练和回滚；灰度关注切流、人群规则、新旧兼容、监控与放量/回退条件。只有存在需求时才启用，cases 整合，specialist 辅助。
- AI 产品关注效果基线、分布与长尾、鲁棒性、公平性、数据隐私、幻觉、拒答、工具调用和评测版本。模型非确定性不能承诺 temperature=0 就逐字相同。使用 AI 帮写测试不等于被测对象是 AI。
- 安全/无障碍/兼容标准使用项目约定版本；第三方提到的 OWASP 2021、ISO 25010、IEEE 829 等不自动代表最新认证，也不强制无关场景凑数量。
- 正式 API Excel 主表按用户九列：接口名称、用例 ID、用例名称、请求方式、请求 URL、请求参数、请求头、预期结果、优先级。测试点评审放辅助表。追溯、依赖、执行结果和覆盖矩阵分辅助表，一行一条关系；回读内容并检查渲染可读性。用户当前模板优先。
- 质量度量由 strategy 整合：需求/风险覆盖列分子分母及版本；代码覆盖只读真实工具结果；缺陷密度标 KLOC/需求等单位；逃逸率按同版本窗口的线上缺陷/(上线前+线上缺陷)。零分母为 N/A，不拿行业示例作项目门禁。
- ROI = (有证据的收益 - 总投入)/总投入；列周期、货币/工时单位、初建/维护/运行成本及人工基线。估算单列假设和区间，不编造“避免的损失”，不重复计省时和缺陷收益。缺成本只做指标框架。

## 3. 统一中文触发语句

用户正常说需求即可，下面是例句，不是必须背诵的口令。

| 直接这样说 | 主责与顺序 |
|---|---|
| 分析这份需求，给开发自测清单 | requirements；必要时引用 review 风险卡 |
| 给这个版本做测试计划和排期 | strategy |
| 按这个 Excel 模板写接口测试用例 | cases；specialist 补专项 |
| 补 ERP、数据迁移或灰度测试用例 | cases + 对应专项 |
| 评审这些用例，查漏测和重复 | review；不自动改原用例 |
| 评审并修好这些用例 | review -> cases -> review 复核改动 |
| 根据这次代码变更选回归范围 | review；要排期再交 strategy |
| 生成可导入 XMind 的 Markdown | xmind |
| 生成能直接打开的 .xmind 测试点文件 | xmind_file |
| 把这些完整用例转成 .xmind，保留步骤 | cases 既有基线 -> xmind_file 转换脚本 |
| 按接口文档生成自动化脚本，先别运行 | api_execution；设计源复用 cases，零目标请求 |
| 在这个测试环境执行这组接口用例并出结果 | api_execution -> 执行报告；原用例和断言是依据 |
| 生成 JMeter 压测脚本 | jmeter；不自动压测 |
| 在已授权环境按这些参数运行 JMX | jmeter 执行 -> performance_report 分析 |
| 分析这个 JTL 并出性能报告 | jmeter 统计 -> performance_report 整合，不重跑 |
| 分析这些压测截图 | performance_report |
| 帮我提 Bug / 查单条 Bug 根因 / 统计 Bug Excel | bug_report / root_cause / bug_metrics |
| 跟踪缺陷状态、责任人与复测结果 | specialist；写平台按当前授权与连接 |
| 汇总功能测试报告并生成 Word | strategy -> delivery_report |
| 计算本版本测试效率、逃逸率和自动化 ROI | strategy；bug_metrics 提供可信缺陷统计 |
| 先需求分析，再计划、用例、评审和执行报告 | requirements -> strategy -> cases -> review -> 实际执行 -> 统计/报告；只运行材料齐全且已授权阶段 |

## 4. 执行环境与维护

- 通用测试规则优化按正文第 1.2 节统一维护：中央正文/补充/清单、C 盘入口、D 盘全局规则和项目模板、受影响的整理视图同步验证。每次测试请求轻量检查中央版本和相关文件状态，有变化再重读；不要求用户逐项目复制规则。
- 行为规则版本与 Skill 文件版本分别记录；本次仅优化加载与维护规则，既有 Skill 版本、适配说明和哈希保持原证据。后续 Skill 有实际修改时再更新其索引与验证结果。
- Codex 隔离 Python：<本次已核实的Python解释器>；不可把 WorkBuddy 已安装 7 个包当作全部 API 依赖齐全。
- 本机 JMeter：<本次已核实的JMeter可执行文件>。复用已有可执行文件，调用时显式 --jmeter；不改全局 PATH/JAVA_HOME/JMETER_HOME。它是本机依赖，不打包进规则迁移包。
